# Screen Off MVP 实施方案

状态：进行中  
创建日期：2026-08-31

## 目标

交付一个可直接分发的 macOS 菜单栏 App，使远程使用中的 MacBook 保持在线，并在没有物理输入时将内建屏幕和键盘背光降至最低。

## 不变量

- 原生 SwiftUI + AppKit/IOKit，不引入 GPUI 或跨平台框架。
- 首版仅支持 Apple Silicon MacBook、macOS 14+、内建屏幕与键盘。
- 所有系统状态修改必须可恢复；合盖能力不得依赖 UI 进程永远存活。

## 阶段 1：项目骨架

交付内容：

- 菜单栏快捷窗口、独立设置窗口和偏好持久化。
- XcodeGen 工程、统一构建脚本和 Codex Run 入口。
- 需求、架构、安全边界与待办文档。

验收：工程可生成并编译；App 启动后只出现在菜单栏；设置能够持久化。

## 阶段 2：普通保持唤醒

交付内容：

- 使用 IOKit 创建和释放 `PreventUserIdleSystemSleep` 断言。
- 使用 `SMAppService.mainApp` 管理登录启动。
- 菜单栏显示真实状态和最小错误信息。

验收：

- 开启后 `pmset -g assertions` 显示 Screen Off 断言。
- 关闭开关或退出 App 后断言消失。
- 登录启动可开启、关闭并在系统设置中观察。

这一阶段可单独发布，作为轻量保持唤醒工具使用。

## 阶段 3：无光运行

交付内容：

- 使用 `IOHIDManager` 记录物理输入时间，不依赖具体远程软件。
- 动态解析 `DisplayServices`，读取、降低并恢复内建屏幕亮度。
- 动态解析 `CoreBrightness`，读取、关闭并恢复键盘背光。
- “立即关闭屏幕”和自动计时共用同一个状态机。

验收：

- UU 远程持续输入不恢复本地亮度。
- 真实键盘、触控板或鼠标输入恢复暗屏前亮度。
- 关闭开关、退出 App 和能力调用失败均不会遗留错误亮度。
- 无背光键盘或私有符号缺失时，其余功能仍正常。

这一阶段可单独发布，提供完整的 Screen Off 核心价值。

## 阶段 4：合盖保持唤醒

交付内容：

- 通过 `SMAppService` 安装签名 Helper，并使用受限 XPC 接口通信。
- Helper 仅封装 `pmset disablesleep` 的启用、续租、停用和查询。
- 30 秒续租、90 秒超时恢复；拔掉电源立即恢复。
- App 启动时检查异常遗留状态，并提供明确恢复入口。

验收：

- 接通电源时合盖后 UU 远程连接持续可用。
- 拔掉电源、正常退出、强制终止 App 和 Helper 租约超时后，系统恢复默认睡眠策略。
- 未安装 Helper 或拒绝授权时，普通保持唤醒和无光运行不受影响。

这一阶段可独立发布，作为高级能力启用。

## 分发

- 使用 Developer ID Application 对 App 与 Helper 签名。
- 完成 Hardened Runtime、公证与 stapling。
- 产出 DMG，并提供卸载与手动恢复睡眠设置说明。

## 回滚

- 普通唤醒：释放全部 IOKit 断言。
- 屏幕与键盘：恢复本次会话保存的原值。
- 合盖模式：Helper 执行 `pmset -a disablesleep 0` 并清除租约。
- 删除 App 前必须先停用登录项和 Helper；分发包提供明确卸载步骤。

## 最脆弱假设

方案假设 `IOHIDManager` 能在目标系统上稳定区分物理设备输入与 UU 等软件注入事件。验收必须以真实 UU 会话验证；若目标系统无法可靠区分，自动恢复功能降级为显式快捷键恢复，不以高层 `CGEvent` 代替物理输入判断。
