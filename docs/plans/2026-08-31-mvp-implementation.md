# Screen Off MVP 实施方案

状态：阶段 1–5 已实现，签名更新链路已验收，等待物理合盖与连续唤醒复验
创建日期：2026-08-31
更新日期：2026-09-02

## 目标

交付一个可直接分发的 macOS 菜单栏 App，使远程使用中的 MacBook 保持在线，并在没有物理输入时将内建屏幕和键盘背光降至最低。

## 不变量

- 原生 SwiftUI + AppKit/IOKit，不引入 GPUI 或跨平台框架。
- 首版仅支持 Apple Silicon MacBook、macOS 14+、内建屏幕与键盘。
- 所有系统状态修改必须可恢复；合盖能力不得依赖 UI 进程永远存活。

## 阶段 1：项目骨架 ✅

交付内容：

- 菜单栏快捷窗口、独立设置窗口和偏好持久化。
- XcodeGen 工程、统一构建脚本和 Codex Run 入口。
- 需求、架构、安全边界与待办文档。

验收：工程可生成并编译；App 启动后只出现在菜单栏；设置能够持久化。

## 阶段 2：普通保持唤醒 ✅

交付内容：

- 使用 IOKit 创建和释放 `PreventUserIdleSystemSleep` 断言。
- 使用 `SMAppService.mainApp` 管理登录启动。
- 菜单栏显示真实状态和最小错误信息。

验收：

- 开启后 `pmset -g assertions` 显示 Screen Off 断言。
- 关闭开关或退出 App 后断言消失。
- 登录启动可开启、关闭并在系统设置中观察。

这一阶段可单独发布，作为轻量保持唤醒工具使用。

## 阶段 3：无光运行 ✅

交付内容：

- 使用 `IOHIDManager` 记录物理输入时间，不依赖具体远程软件。回调只更新时间戳。
- 动态解析 `DisplayServices`，读取、降低并恢复内建屏幕亮度。
- 动态解析 `CoreBrightness`，读取、关闭并恢复键盘背光。
- “立即关闭屏幕”和自动计时共用同一个状态机。

验收：

- UU 远程持续输入不恢复本地亮度。
- 真实键盘、触控板或鼠标输入恢复暗屏前亮度。
- 关闭开关、退出 App 和能力调用失败均不会遗留错误亮度。
- 无背光键盘或私有符号缺失时，其余功能仍正常。

这一阶段可单独发布，提供完整的 Screen Off 核心价值。

## 阶段 4：合盖保持唤醒 ✅（方案已变更）

原计划安装特权 Helper 执行 `pmset disablesleep`。实测表明不需要：
`PreventSystemSleep` 是公共断言类型，系统本身就限定它仅在接通电源时生效，
与 `caffeinate -s` 同源。因此整个 Helper、XPC 和租约机制被移除。

交付内容：

- 使用 IOKit `PreventSystemSleep` 断言，与普通空闲断言分开持有、分开释放。
- 监听 `IOPSNotificationCreateRunLoopSource`，供电来源变化时立即重算断言。
- 拔掉电源时主动释放断言，并在界面上说明「需接通电源，当前已暂停」。

验收：

- 断言创建与释放已通过 `pmset -g assertions` 实测。
- 合盖后的实际保持行为需要物理合盖复验。
- 拔掉电源后的回退需要物理拔线复验。

## 阶段 5：原生设置与应用内更新 ✅

- 设置窗口参考 One Switch 的原生偏好设置结构，使用功能、通用、关于三个顶部标签。
- 菜单栏窗口收紧为 304 pt，设置和退出改为灰色图标按钮。
- 修复手动关屏后的唤醒门控：固定 300 毫秒保护期不再被输入延长。
- 键盘背光改为屏幕关闭的伴随选项，空闲最短时长为 1 分钟。
- 集成 Sparkle 2，配置 GitHub Release Feed、EdDSA 公钥、签名 Feed 和提取前验签。

更新链路已使用同一公司 Developer ID 与 Sparkle 公钥完成 0.1.0 → 0.1.1 真实升级，
下载、验签、替换与自动重启均通过。连续 10 轮手动关屏与物理输入唤醒仍需单独复验。

## 回滚

- 普通唤醒与合盖模式：释放全部 IOKit 断言即可，系统无残留设置。
- 屏幕与键盘：恢复快照中保存的原值并清空快照。
- 异常终止：下次启动时读取快照自动还原。
- 删除 App 前先停用登录项；分发包提供明确卸载步骤。

## 最脆弱假设（已验证）

假设：`IOHIDManager` 能稳定区分物理设备输入与软件注入事件。

实测结论见 [真机验证记录](../reference/verification-2026-09-01.md)：

- `CGEventSource` 的 `hidSystemState` **会**被软件注入重置，不能用作物理输入判据。
- `IOHIDManager` 回调**不会**被软件注入触发，可以用作判据。

仍需在真实 UU 会话中复验：UU 若改用更底层的 `IOHIDPostEvent` 注入，结论可能不同。
未取得「输入监控」授权时降级为事件源读数，此时无法区分远程输入，界面会明确说明。
