# In-App Updates and Releases

Screen Off uses Sparkle 2 to update the plain app bundle distributed under Developer ID. The update
archive and the appcast are hosted on two independent update origins:

- GitHub: `https://github.com/imetn/ScreenOff/releases/latest/download/appcast.xml`
- US1: `https://frameflowtech.com/updates/screenoff/latest/appcast.xml`

Before manual and scheduled checks, the app probes both HTTPS feeds concurrently, validates their
Ed25519 signatures, and makes a one-byte range request to each actual ZIP download URL. Requests
have a four-second inactivity timeout and a six-second resource limit per request. Among reachable
sources, a newer signed build wins; for the same build, the faster completed probe wins. A source
with a working feed but an unreachable archive is excluded. If neither works, manual checks show
an error and scheduled checks remain quiet. Cancellation stops the probes.

The mirror serves the **original signed bytes**, including the original GitHub enclosure URL.
`SPUUpdaterDelegate` selects the feed and rewrites only the outgoing ZIP request to the selected
origin. Sparkle independently verifies both the feed and archive as usual. If a feed or ZIP request
later fails, the updater retries the other reachable source once, without a source-selection prompt.
An already approved update is automatically retried only when the complete signed appcast item is
identical. Signature, extraction, installation and cancellation errors are not silently retried.
Older mirror builds are excluded from a retry of a newer release. This does not guarantee
connectivity from every mainland network; the available routes still depend on the user's ISP.

Legacy preview versions through 0.1.1 only know the GitHub source. Their first upgrade to a
build containing this feature requires working GitHub access or a manual download of the new DMG
from the server. Copying the existing release to US1 does not retrofit old app binaries.

The canonical bundle identifier is `com.frameflowtech.screenoff`. Public versions through 0.1.1 used
`com.ethan.screenoff`. The app imports allowlisted preferences, shortcut data, and recovery snapshots
once without overwriting values in the new domain; it never copies privacy grants or update caches.
Input Monitoring must be granted again, and login-item registration must be checked for the new ID.
The legacy identifier migration was verified through a signed loopback feed: installer IPC,
replacement, and automatic relaunch succeeded, with the resulting signature matching the notarized
release. A deliberately corrupted ZIP was rejected before installation and left the original app
unchanged. Repeat the upgrade check for future releases.

Version 1.0.0 is the clean public repository baseline. Its internal build number is 4, continuing the
previous build sequence so existing installations can upgrade. Never reset `CURRENT_PROJECT_VERSION`
when changing the public version or repository history.

The app enables both `SURequireSignedFeed` and `SUVerifyUpdateBeforeExtraction`: the signed feed is
verified first, then the archive's Sparkle EdDSA signature.

## One-Time Setup Before Releasing

1. Sign in to the company developer account in Xcode (26.6 or a later stable release) using team
   `PRYY9PKKUP`.
2. Create or download the company `Developer ID Application` certificate through Xcode's Direct
   Distribution.
3. Keep the private key generated by Sparkle's `generate_keys` in the login keychain; only the public
   key lives in the repository.
4. Sign in to the GitHub CLI with an account that can publish releases for `imetn/ScreenOff`.
5. Store the company notarization credentials as the keychain profile `ScreenOff-Notary` with
   `notarytool store-credentials`.
6. Install the open-source DMG builder: `brew install create-dmg`.
7. Ensure SSH access to US1 `5.78.223.34` and the route below are configured. The publish script uses
   the existing local operations key at `$HOME/Projects/keys/id`; override with
   `SCREENOFF_MIRROR_SSH_KEY` if needed. The default SSH target is `root@5.78.223.34`, overridable
   with `SCREENOFF_MIRROR_HOST`. Host keys must already be trusted. No SSH or signing key is shipped
   in the app or uploaded with release assets.

Never publish updates with a personal team, `Apple Development`, `Apple Distribution`, or ad-hoc
signed packages.

## Every Release

1. Bump `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` in `project.yml`.
2. Add the matching `Docs/releases/v<version>.md`, commit, and keep the working tree clean.
3. Run `./Script/release.sh build` to produce and verify the local artifacts.
4. Run `./Script/release.sh --publish` to push `main`, create the GitHub Release, and automatically
   upload and verify the same artifacts on US1.
5. Run a real "Check for Updates" and install from the previous stable version.

The release script performs, in order: Xcode archive, automatic company Developer ID signing, upload
for Apple notarization, export of the stapled app, Gatekeeper assessment, ZIP packaging, signed
appcast generation, the custom drag-to-install DMG, separate DMG signing and notarization, and the
GitHub Release, and US1 mirror synchronization. Both sources must pass verification before the
publish command reports success.

### Mirror storage and recovery

US1 stores releases outside the website checkout in `/var/www/screenoff-updates/v<version>/`.
`latest` is an atomically replaced symlink. The Nginx snippet in
`Script/server/screenoff-updates.conf` is installed at `/etc/nginx/snippets/screenoff-updates.conf`
and included inside the `frameflowtech.com` TLS server in
`/etc/nginx/sites-enabled/frameflow-web.conf`. Validate with `nginx -t` before reloading Nginx.
Website deployments must preserve this include. The existing domain/TLS routing is reused;
there is no new DNS record, application server, database or R2 bucket.

`Script/sync_update_mirror.sh` verifies the Sparkle feed and ZIP signatures locally, uploads into
an inaccessible staging directory, verifies all SHA-256 hashes and release metadata on US1,
then publishes under a lock. Existing version directories are immutable; older builds cannot
replace `latest`. Versioned files have long-lived immutable caching; `latest` uses `no-store`.
After publication the script downloads all four public artifacts and compares their bytes with
the originals, including the `latest` feed. Interrupted uploads cannot expose a partial release.

If GitHub publication succeeds but mirror synchronization fails, the command exits unsuccessfully.
Retry only the synchronization step; do not rebuild or recreate the GitHub release:

```bash
./Script/sync_update_mirror.sh v1.0.0 /absolute/path/to/ScreenOff/build/releases/v1.0.0
```

For a release published from another machine or the GitHub UI, first download its four assets
with `gh release download` into a new directory, then run the same sync command. Automatic
synchronization is part of `release.sh --publish`; arbitrary GitHub UI uploads do not trigger it.
Public first-install downloads are available at
`https://frameflowtech.com/updates/screenoff/latest/ScreenOff.dmg`.

Mirror acceptance checks cover byte-for-byte equality of all four public assets and the latest
feed, range requests, cache headers, hidden staging paths, and idempotent synchronization. The
33-test suite passed, including source failures, stale feeds, tampering, and retry boundaries.
The signed app's real "Check for Updates" selected US1 and completed successfully; cancellation
followed by another check also succeeded. An isolated Sparkle fixture injected an HTTP 404 after
successful mirror preflight, and the same check switched to GitHub without an intermediate error
prompt. Production assets were not changed for this failure test.

Only the ZIP update archive goes into Sparkle's appcast input directory. The DMG is the first-install
asset and is excluded from appcast generation so that one bundle version is never listed as two
duplicate updates.

The DMG opens a 560 × 360 Finder window with the Screen Off and Applications icons, a drag-direction
hint, and a custom background. The background carries only the product name and generic artwork, with
no fixed Chinese or English copy; the source is `Script/assets/dmg-background.svg`.

## Uninstalling

1. Turn off "Launch at login" under General, then quit Screen Off.
2. Move `/Applications/ScreenOff.app` to the Trash.
3. To remove preferences as well, run `defaults delete com.frameflowtech.screenoff`; a normal uninstall does
   not need this step.

## Security Boundaries

- Developer ID and Apple notarization prove the app's origin; the Sparkle EdDSA signature proves the
  update archive comes from the publisher.
- The appcast itself must be signed with the same Sparkle key, and every URL must use HTTPS.
- System profiling is disabled; no device profile is attached to appcast requests.
- Screen Off does not use App Sandbox, so Sparkle's sandboxed XPC services are not enabled.
- The export must verify `TeamIdentifier=PRYY9PKKUP`; otherwise the release script fails immediately.
- The DMG must be signed by the same company `Developer ID Application` certificate, notarized
  separately, and stapled.
